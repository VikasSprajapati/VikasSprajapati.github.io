Case study 01 Live in production Internal tool

Search Optimizer: an AI agent that fixes Shopify SEO, AEO and GEO issues and proves it worked.

An internal platform I designed, built and shipped end to end. It audits every store with eight tools, scores them on one comparable scale, then uses an autonomous AI agent to fix the issues. A fix only counts when the audit tool confirms it.

My roleProduct decisions, full-stack build and deployment, working with an AI coding assistant
Used byThe SEO team and management
ScaleA portfolio of 20–25 Shopify stores

The problem

Store performance depends on classic search (SEO), answer engines (AEO) and AI search engines like ChatGPT and Perplexity (GEO). The team's workflow couldn't keep up with all three.

Fragmented audits

Results came from many separate tools, and the scores weren't comparable.

Manual fixing

Fixing meant uploading audit files to a chat AI and copying the edits into Shopify by hand.

No proof

Nobody could tell which fixes had actually worked.

What the app does

One workspace per store, and one portfolio view across all of them.

AuditUnified audits

Eight tools run per store: SEOmator (365 rules), Google PageSpeed (median of 3 runs), a GEO optimizer, AI citability, brand presence, rich results, a deep site crawl and Search Console. They combine into Overall, SEO, AEO and GEO scores with configurable weights.

UnderstandPortfolio dashboards

A store switcher, prioritised opportunities, trends and store comparison. Each store has Overview, Issues, Pages, Tool reports and History tabs, with period comparison, interactive charts and CSV/Excel export.

FixAI fixes, the core feature

An autonomous agent (Claude or Gemini, using tool calls) fixes issues in a copy of the store's theme and, through the Shopify Admin API, in products, pages, blog posts, SEO titles and alt text.

TrustSafe by design

Every change goes through preview, review, publish and one-click roll back, with an automatic theme backup. Careful mode makes no design changes; Fix it mode does.

ControlCost and control

Spend limits per fix, batch planning with estimates, and skip or stop for batches or single issues mid-run, with a live per-issue status list.

ShowVisible progress

"Why did the score change?" explanations, before/after for every fix, a celebration screen for each confirmed gain, a Fixed issues view with export, an activity log, and "Learn more" guidance on every issue.

An agent that checks its own work

The agent doesn't get to declare victory. Every fix goes through a verification loop before it is counted.

It sees the real page

It views the actual rendered pages on a live preview served by Shopify CLI.

It runs the audit's own rule

It executes the audit tool's exact rule against its changes.

It retries with evidence

Issues that still fail go back to it automatically, along with the evidence.

"Fixed" only counts when the audit tool agrees.
Measurement built to be honest
  • Like-for-like comparisons that cancel out scoring-settings changes
  • Per-page progress and a confirmation audit that waits for Shopify to update the store
  • "Can't be fixed by an app" detection based on evidence
  • A highest-reachable-score estimate for each store
  • An AI track record per issue type and per AI model

Results

First measured run of the rebuilt agent, on one store: SEO score +1, with every confirmed fix verified by the audit tool itself.

Measured run40% fewer

Page-level problems on that store, down from 35 to 21

Measured run2 of 7

Issues fixed and confirmed by the audit. The preview check had predicted exactly those 2.

Measured run$3.09

Total AI cost of the whole run

Scale8 tools, 1 score

Audit tools unified into comparable Overall, SEO, AEO and GEO scores per store

Scale365 rules

Checked per store by SEOmator alone, alongside PageSpeed, crawl and Search Console data

Scale20–25 stores

Managed from one app by the SEO team and management

The bigger win: finding out why earlier fixes looked ineffective

Only about 10% of issues were being confirmed. Root-cause analysis found four causes, and the redesign fixed all of them.

  • Scoring settings were changing mid-test
  • The AI was working without seeing the pages
  • Issues were being routed to the wrong place
  • The confirmation audit ran before the store had updated

Case study 02 Live in production, 2026 Internal tool, company SSO

Commerce Optimizer: one trusted view of every store, with AI that proposes and people approve.

A multi-store e-commerce intelligence platform. It brings each Shopify store's sales, advertising (Google, Meta, Bing), web analytics (GA4) and on-site behaviour (Microsoft Clarity) into one dashboard, flags what changed and why, and proposes fixes that a person approves before anything changes.

My roleDesigned and built the full application: architecture, back end, front end, data pipeline and AI features, working with Claude Code as an AI pair-programmer
Built forAn e-commerce company running several Shopify stores
WorkflowTask branches, UAT, then production on GitLab. A DevOps colleague handled server deployment and sign-in.

The problem

The team checked Shopify, three ad platforms and two analytics tools separately, and reconciled the numbers by hand. Commerce Optimizer gives one trusted view per store and across all stores, explains changes in plain language, and turns analysis into approved actions.

Impact6 sources

Shopify, Google Ads, Meta Ads, Bing Ads, GA4 and Clarity in one view, replacing manual cross-checking

ImpactTo the cent

Sales figures reconcile exactly with Shopify's own sales reports

Impact±20%

Cap on AI-proposed budget changes; every action is approved, logged and reversible

Engineering85% smaller

Main JavaScript bundle, from 814 kB to 123 kB, through code splitting

Engineering~0.3 s

Revisited pages appear from cache, with duplicate requests removed

Engineering65 tests

Unit tests, plus linting and responsive checks on phone, tablet and desktop

What the app does

A portfolio view across all stores, and a workspace for each one.

OverviewPortfolio overview

KPI cards with trends (sales, orders, AOV, ad spend, ROAS, MER, conversion rate), a checkout-loss summary, an interactive trend chart, "what moved sales" and a store comparison table.

AnalyticsPer-store analytics

Sales with refunds, customer mix, channels, discount codes and fulfilment speed; marketing with an Ads health score; traffic with the GA4 funnel and Clarity frustration signals.

AdvertisingOne ads dashboard

Google Ads, Meta Ads and Bing Ads compared on a single page, with campaign-level flags for spend without return.

InsightsInsights engine

Rule-based alerts with evidence, likely causes, money impact and next steps: sales and ROAS drops, refund spikes, unshipped orders, checkout abandonment, "page not found" traffic and budget-capped winning campaigns.

HealthAds health checks

A 0–100 score from five data-driven checks: conversion tracking, non-converting search terms, budget-limited winning campaigns, Meta ad fatigue, and spend without sales.

AIAI layer

Claude, with Gemini as fallback: root-cause analysis of any insight, weekly strategy briefs per store and across all stores, and an "Ask AI" chat grounded in the store's own data.

  • Date filtering everywhere: presets and custom ranges up to a year, each compared with the previous period, in each store's own time zone
  • Exports: branded PDF reports, Excel workbooks and CSV, for any period or set of stores
  • Store onboarding: a guided "Add store" flow with automatic syncing
  • Connection health: plain-language diagnosis when a data source stops working

AI that proposes, people approve

The AI can act on live ad accounts, which is exactly why it is not allowed to act alone.

The AI proposes a fix

Pause or enable campaigns, change budgets (capped at ±20%), add negative keywords, or create discount codes.

A person approves

Each proposed action is reviewed and approved individually before it runs.

Everything is reversible

Guardrails on every action, a full audit log and one-click undo.

Nothing runs until a person approves it.
AI cost transparency
  • Every request is stored with its answer, tokens, time and cost
  • A History & Costs view shows spend by feature, store and day
  • Waste is visible: money lost on failed requests, and savings from caching
  • Spend is controlled by a monthly budget cap and free reuse of identical analyses

Technical highlights

The parts that make the numbers trustworthy and the AI affordable.

DataA resilient sync pipeline

A background worker with database-level job claiming (FOR UPDATE SKIP LOCKED), incremental syncs from every 30 minutes to daily by source, a 180-day history import via Shopify's GraphQL bulk operations, and re-checks of recent ad days because conversions arrive late.

AccuracyTwo refund bases, one truth

Refund accounting supports two reporting bases: one reconciles with Shopify's reports to the cent, the other suits judging ad efficiency. Ratios are computed from period totals, never by averaging daily ratios.

LimitsBudgeting a tight API

Microsoft Clarity's export API allows 10 requests a day per project, so the app budgets itself to at most 8 and keeps raw responses so data can be rebuilt without new calls.

AI engineeringReliable, cheap AI

Structured JSON outputs validated with Zod, prompt caching of store facts that cut follow-up costs, automatic reuse of identical analyses, retries when an answer is cut off, and per-request cost metering with AsyncLocalStorage.

PerformanceFast to load, fast to revisit

Code splitting took the main bundle from 814 kB to 123 kB. Data loading moved to TanStack Query, so a revisited page appears from cache in about 0.3 s, duplicate requests disappear and data refreshes in the background.

SecurityPrivacy by design

Platform tokens encrypted at rest (AES-256-GCM), no customer names, emails or addresses stored for abandoned checkouts, and company SSO with domain-restricted access.

  • Database: MySQL 8 on AWS RDS, shared with another internal app through prefixed tables and a separate migration history, with composite keys and indexes designed per query
  • Quality: 65 unit tests, Oxlint including the React Hooks rules, Prettier, and layouts checked in light and dark mode
